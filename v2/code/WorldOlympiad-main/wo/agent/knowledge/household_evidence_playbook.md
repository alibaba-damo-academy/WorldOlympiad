# Household task and repair contract

Use the current goal as the single source of task scope and priority. The nine-family household catalog is developed in parallel; there is no obsolete three-pilot prerequisite. Historical bench_v1 and failed development versions remain unchanged.

Before curated asset generation, establish a real household need, concrete useful result and an observable success condition. A contact event does not prove assembly, and an already-upright bottle does not prove reorientation. Keep design drafts outside live tasks until their meaning and physical capability are reviewed. Debug fixtures are not automatically showcase samples.

The native agent owns observation, diagnosis, the smallest general repair, meaningful regression tests, promotion and real validation. Root reviews evidence and the code. Old notes claiming native transforms/loaders/framing are root-only are obsolete. Running scene jobs do not prevent independent repair of an already reproduced defect.

For each failure:
1. Bind the latest job, task hash, published SDF/URDF/layout and certificate/trajectory. Inspect new physical/native images and video frames; concepts and historical artifacts are not current physical evidence.
2. Reproduce the exact failing interface and geometry. Tests must model the actual production boundary, including pose/units/quaternion conventions; a convenient mock is not proof of the real contract.
3. Change one general capability or one bounded task-content factor. Preserve history, collision checks, predicates, audit tolerances, official model inference and action/observation protocols. Never add a case-specific coordinate correction.
4. Run focused tests and promote the candidate. Validate the failed registered stage and at most one relevant existing control through the path changed: native loader/layout/camera changes use scene_check; expert/planning changes use expert_check. Reuse bound references.
5. Read the actual validation result and new native images. Unit-test success or a queued job is not a completed repair. If validation fails, diagnose its new evidence before another change or submission.

Stage order: final physical scene/layout -> reference (creates trajectory/camera/certificate) -> scene_check (creates native input diagnostics) -> model episodes once the current run's references are ready -> scores/report. Never require a producer's future output before starting that producer. Dependency or input failures are not model outcomes or legal NA.

Use the absolute project Python environment for diagnostics. The autoresearch environment already has imageio_ffmpeg for actual frame extraction. Record concise findings and evidence paths; the round log retains actual test/promotion/job returns. All nine still require root review of useful task semantics, unsolved initial state, recognizable assets, visible functional geometry and readable complete action/result video.
